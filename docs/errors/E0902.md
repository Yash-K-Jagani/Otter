# E0902 — misplaced variadic marker

`...` is written where a variadic parameter cannot appear.

## Cause

A C function may take a fixed list of parameters followed by `...`, meaning "and
then any number of arguments whose types the C compiler does not check". Yashy
adopts that marker only for the declaration of such a function, and only in the
last position, because everything after it has no parameter to be checked
against.

There are three places the marker cannot go:

* on a Yashy `fn` — a Yashy function has a fixed signature, so there is nothing
  for `...` to describe;
* in a function type such as `fn(*const u8, ...) -> i32` — the type describes a
  call Yashy makes, and Yashy has no variadic functions;
* anywhere but the end of an `extern` declaration's parameter list.

## Example

```yashy
fn show(args: ...) {
    print("hi");
}

fn main() {
    show();
}
```

```text
variadic.ya:1:15
error[E0902]: `...` is only allowed as the last parameter of a declaration inside an `extern` block
fn show(args: ...) {
              ^^^
  docs: https://yashy.dev/errors/E0902
```

The same marker after another parameter is rejected for the same reason:

```yashy
extern "C" {
    unsafe fn printf(fmt: *const u8, ..., extra: i32) -> i32;
}
```

```text
variadic.ya:2:40
error[E0902]: `...` must be the last parameter
    unsafe fn printf(fmt: *const u8, ..., extra: i32) -> i32;
                                       ^^^
  docs: https://yashy.dev/errors/E0902
```

## Fix

Write the marker only as the last element of an `extern` declaration:

```yashy
extern "C" {
    unsafe fn printf(fmt: *const u8, ...) -> i32;
}
```

Remove it from a Yashy `fn` and from function types. A function that takes a
fixed list of parameters should name each one.
