# E1400 — double close

A resource is released twice, or released in the wrong state.

## Cause

Resources carry a state: a mutex is `Unlocked` or `Locked`, a channel is `Open`
or `Closed`, a pointer from `alloc` is `Allocated` or `Freed`. Each operation
requires a particular state and moves the resource to another:

- `mutex_lock(m)` requires `Unlocked`, produces `Locked`;
- `mutex_unlock(m)` requires `Locked`, produces `Unlocked`;
- `mutex_free(m)` requires `Unlocked`, produces `Freed`;
- `chan_close(c)` requires `Open`, produces `Closed`;
- `chan_free(c)` requires `Open`, produces `Freed`;
- `.free()` requires `Allocated`, produces `Freed`.

Releasing a resource a second time, or releasing it in the wrong state, is
`E1400`. A disagreement between two paths at a merge is the same error, with
both states named.

## Example

```yashy
fn main() {
    let c = chan_new(4);
    chan_close(c);
    chan_close(c);
}
```

```text
main.ya:4:5
error[E1400]: `c` is in state `closed`, but this operation requires `open`
    chan_close(c);
    ^^^^^^^^^^^^^
  docs: https://yashy.dev/errors/E1400
```

## Fix

Release the resource once, on every path, and only when it is in the state the
operation expects. If the two paths disagree about the state, make them agree:
release on both, or on neither and release after the merge.
