# E0901 — malformed extern declaration

`link_name` is written where it is not allowed, or its value is not a non-empty
string literal.

## Cause

`link_name` changes which symbol an `extern` declaration resolves to. It is
meaningful only on a declaration inside an `extern` block, because only there is
there a C symbol to name. A Yashy `fn` is compiled by Yashy and already has a
symbol, so `link_name` on one has nothing to do. The value must be a plain,
non-empty string: an empty name is not a symbol the linker can find, and an
interpolated string is not known until the program runs, which is too late.

## Example

```yashy
fn twice(n: int) -> int link_name "twice" {
    return n * 2;
}

fn main() {
    print(twice(21));
}
```

```text
link.ya:1:1
error[E0901]: `link_name` is only allowed on a declaration inside an `extern` block
fn twice(n: int) -> int link_name "twice" {
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

```

## Fix

Write `link_name "symbol"` after the signature of a declaration inside an
`extern` block, and write a literal name:

```yashy
extern "C" link "m" {
    unsafe fn c_sqrt(x: f64) -> f64 link_name "sqrt";
}
```

Remove it from an ordinary `fn`. An empty `link_name ""` is the same mistake:
name the symbol, or delete the clause and let the declaration's name be the
symbol.
