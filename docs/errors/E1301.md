# E1301 — unsafe call in a declared function

An `unsafe` call appears in a function that declared it would not make one.

## Cause

`unsafe` at a call site is the acknowledgement that the call can do something
the language cannot check — `unsafe free(p)` releases memory by hand, and a
call into an `extern` block leaves the program's guarantees at the door.

A function that declares an effect makes a promise about its body:

- `pure fn` promises no IO and no unsafe calls;
- `io fn` promises IO and nothing else;
- `async fn` promises the same.

An `unsafe` call inside one of those bodies breaks the promise, and that is
`E1301`. The call is reported, not the declaration, because the call is the
thing to move.

An unannotated `fn` makes no promise. `unsafe free(p)` inside it is legal and
simply makes the function's inferred effect `unsafe`, which every *declared*
caller then has to account for. An `unsafe fn` may of course make the call.

## Example

```yashy
io fn report(path: string) {
    let buf = read_file(path);
    unsafe free(buf);
}
```

```text
main.ya:3:12
error[E1301]: `free` is an unsafe call, but `report` is declared `io`
    unsafe free(buf);
           ^^^^^^^^^
  docs: https://yashy.dev/errors/E1301
```

## Fix

Declare the function `unsafe`, or move the call into one:

```yashy
unsafe fn release(buf: string) {
    unsafe free(buf);
}

io fn report(path: string) {
    let buf = read_file(path);
    release(buf);
}
```

If the call is unnecessary, remove it: `unsafe` is a statement about what the
program does, not a formality to be silenced.
