# Phase 10 — Async: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship one async model that is provably race-free, structured, cancellable and debuggable — not a framework ecosystem. An `async fn` compiles to a state machine with an explicit frame; `await` suspends it; `scope` makes every task outlive nothing; and the verifier refuses a lock held across a suspension point.

**Architecture:** `async fn f() -> T` has type `Task[T]`; `await` drives a task to completion on the current executor. Lowering is the one in the phase 3 spike document: a per-function **frame struct** holds every local live across an `await`, and the function body becomes a `poll(frame) -> Poll[T]` match over a resume index. The executor is one type — `yashy-executor`, in the runtime, with a single-threaded mode and a thread-pool mode — and `block_on` is a loop over `poll`. Structured concurrency is `scope { .. }`: children are registered on the scope, and leaving the scope joins or cancels them before continuing. Cancellation is a flag checked at each `poll` entry; a resource held across an await is therefore a resource that must be released on the cancel path, which is exactly what the verifier checks.

**Tech Stack:** `crates/yashy-runtime` (`yashy_thread_spawn`/`join`, `yashy_mutex_*`, `yashy_chan_*` — the primitives already exist and are tested in `tests/threads.rs`), `crates/yashy-codegen/src/fn_gen.rs` (state-machine emission), `yashy-verify` (effects, typestate), `yashy-lsp`, `yashy-bench`.

**Spec:** `docs/superpowers/specs/2026-10-27-yashy-master-design.md` §8 row 10. Index: `docs/superpowers/plans/2026-10-27-yashy-master-plan.md`. Design input: `docs/superpowers/design/2026-11-async-spike.md` (phase 3 Task 9). Predecessor: `2026-10-27-phase-09-macros.md`.

## Global Constraints

See the master index. The ones that bite here:

- No exceptions, no hidden allocation, no implicit coercion. `await` is explicit at every suspension point.
- No new runtime dependencies; the executor is C in `yashy-runtime`.
- Ownership is explicit: a task owns its frame, and a task that escapes its scope is rejected.
- Both operating systems or it is not done — the executor must be exercised on Windows's thread implementation, not only pthreads.
- No unproven claim: "no data races" means the phase 2 rule holds over async captures, tested, not asserted.
- **The state-machine lowering registers in phase 4's pass manager.** `poll` generation is a registered pass (`--opt-list` names it), so `--no-opt=async` disables it for bisecting and the per-pass gate holds it to its own bench row. A lowering that emits IR without registering is a construct with no owner, which phase 4's `HirExpr`-ownership test catches.

## Written cap (this phase)

Carried from the spec and enforced by tests:

- **One executor.** `yashy-executor` with a single-threaded mode and a thread-pool mode. No pluggable runtimes, no `Runtime` trait.
- **No async traits.** A trait method may not be `async`; `E1703` says so and names the synchronous alternative. This is a cap, not an oversight.
- **No generic runtime.** Task handles are `Task[T]` over the existing monomorphisation; no `Future` trait in user code, no combinators library, no `select!`.
- **No async closures.** A `spawn` takes a function and its arguments; the capture rule from phase 2 applies unchanged.

## Review Focus

1. **A local live across an `await` lives in the frame, not on the stack.** This is the whole correctness of the lowering: the LLVM stack frame is gone when the task suspends. A test suspends a task in the middle of a function with 8 live locals, drops the thread that started it, and resumes on another.
2. **A lock held across `await` is `E1702`, and it is a deadlock, not a style issue.** The typestate lattice from phase 2 knows the lock is `Locked`; the async pass knows the next statement suspends. Neither alone is enough, which is why this rule belongs here.
3. **A task may not outlive its scope.** `E1701` when a task handle is returned, stored in a field, or pushed into a collection that outlives the `scope`. Joining is implicit at scope exit; an explicit join is allowed and idempotent.
4. **Cancellation must release.** `scope` cancels unjoined children at exit only after they reach a poll boundary; a cancelled task runs its `defer`s. A test asserts a file handle is closed on the cancel path.
5. **The `async` effect is transitive and enforced.** Calling an async function from a synchronous one is `E1300` with the async callee named; `await` outside an `async fn` is `E1700`. The phase 2 `Effect.async_` flag exists for this and was left false everywhere until now.

- Create: `crates/yashy-runtime/src/executor.c`, `include/yashy_runtime.h` additions
- Modify: `crates/yashy-codegen/src/expr_gen.rs` (`block_on`, `spawn` builtins)

- Modify: `crates/yashy-driver/tests/programs/async_basic.ya`

**Interfaces:**
- Produces:
  ```c
  typedef struct yashy_executor yashy_executor;
  yashy_executor *yashy_executor_new(int threads);   /* 0 = single-threaded */
  void yashy_executor_free(yashy_executor *);
  int yashy_task_spawn(yashy_executor *, void *(*poll)(void *), void *frame, size_t frame_size);
  int yashy_task_poll(yashy_executor *, int handle);  /* 1 ready, 0 pending, -1 failed */
  int yashy_block_on(yashy_executor *, int handle);
  void yashy_task_cancel(yashy_executor *, int handle);
  ```
- Produces: `block_on` is a `poll` loop with a condition variable; `spawn` enqueues; the thread-pool mode runs polls on worker threads, and the single-threaded mode runs them inline on the caller.

- [ ] **Step 1: Write the failing tests** — 10 000 tasks complete; a task spawned from a task completes before `block_on` returns; `--timings` reports `tasks=N`; the executor frees with no leak under the runtime's memory test harness.
- [ ] **Step 2: Watch them fail.**
- [ ] **Step 3: Implement** — the executor owns a queue, a mutex and a condition variable; frames are `malloc`ed and freed on completion, drop or cancel. No work stealing in v1 (the cap says one executor, not one scheduler algorithm), so the queue is a mutex-protected ring buffer and the poll loop is FIFO.
- [ ] **Step 4: Run** `cargo test -p yashy-runtime --test async` → PASS on Windows and Linux.
- [ ] **Step 5: Commit** — `git commit -m "feat(runtime): one executor with single-threaded and pool modes"`
